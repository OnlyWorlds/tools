# Little Lens, read 2026-10-31

Read against the seven lines by the OnlyWorlds maintainer (Kael), at [little-lens `c1721fe`](https://github.com/OnlyWorlds/little-lens/tree/c1721fe) and at https://little-lens.onlyworlds.com, signed out, in a fresh browser with no storage. Little Lens is OnlyWorlds' own tool, so it was read directly rather than through the form. File references are at that commit; the one later commit on `main` (`a89b7bb`) adds a test walk and changes nothing the page ships.

1. **It is what it says.** The URL serves Little Lens (200, "Little Lens · OnlyWorlds", the first screen offers Sign in with OnlyWorlds, a world file, a world folder, the public demo world Moppetopia and the standard's small worlds). The source is public under MIT (`LICENSE`).
2. **Keys stay with the person.** Little Lens asks for no world key and no PIN, and never makes a key on the account (`src/lens/account.ts:1-4`). Signed in, its one account token is held in the page's memory only and is never stored; it is revoked on sign-out and when the page is left (`src/lens/account.ts:26-38`, `src/main.ts:102-113`). Across the sign-in round trip localStorage holds the sign-in's own record (its `state` and PKCE verifier), a time stamp and the address to come back to, and all three are removed on the return, whatever its outcome (`src/lens/signin.ts:21-23,43-62,149-152`). The token is sent only to www.onlyworlds.com, as the bearer (`src/lens/world-read.ts:14,70`). Signed out, after opening a public world, the page's localStorage, sessionStorage and cookies were empty. Its host serves static files only.
3. **It names itself.** Every SDK client it makes passes `client: 'little-lens'` (`src/lens/signin.ts:104,148`, `src/lens/account.ts:72`, `src/lens/members.ts:74`), and its sign-in is registered with OnlyWorlds as `little-lens` at https://little-lens.onlyworlds.com/signin/callback (`GET /api/v2/auth/clients`). It writes nothing to a world: it makes no element, field, folder or world file, so it sends no `X-OW-Client` (the SDK sends that only on element writes), has no fields of its own (no prefix) and writes no producer line. Its only requests other than reads are the sign-in's code exchange (`POST /auth/token`, in the SDK) and the removal of its own sign-in (`DELETE /account/tokens/{id}`, `src/lens/account.ts:32-33`).
4. **It speaks the wire.** It declares `@onlyworlds/sdk` 4.116.0 exactly (`package.json`, the same in `package-lock.json`). Its calls, each a route and method in the API document (https://www.onlyworlds.com/api/v2/openapi.json, read 2026-10-31): `GET /world?world=` and `GET /{type}?world=&limit=&cursor=` (`src/lens/world-read.ts:104,170`), `GET /character/{id}/context` with `world`, `as_of`, `budget`, `components` (`src/lens/draught.ts:136`), and, signed in, `GET /members` (the SDK's `members()`, `src/lens/members.ts:74`), `GET /account/worlds` (the SDK's `listAccountWorlds()`, `src/lens/account.ts:73`), `DELETE /account/tokens/{token_id}` and `POST /auth/token`. It sends a trailing slash (`/world/`, `/character/`) where the document has none; both forms answered 200 keyless. Every world and element id is checked as an id before any request (`src/lens/route.ts:30,47-50,62`). A world file is read through the SDK's `readWorldFile`; it writes no folder and no world file.
5. **What leaves the machine.** Little Lens sends no world data anywhere: a public world is read from www.onlyworlds.com with no key, a signed-in world with the account token to the same host only, and a world file or folder is read in the browser and sent nowhere (`src/lens/file-read.ts:1-9`). An element's picture is loaded only from media.onlyworlds.com, with no referrer; a picture on any other host is named, never fetched, and a file's pictures are never fetched (`src/ui/element-view.ts:29-43`, `src/main.ts:774`). There is no analytics, font or CDN call in the source or the served page. The page's CSP allows connections only to itself and www.onlyworlds.com, and images only from itself and media.onlyworlds.com.
6. **The host.** 200 over HTTPS with HSTS (max-age 31536000); http redirects (301) to https; certificate verified, issued by Google Trust Services (WE1), naming little-lens.onlyworlds.com, valid to 2027-01-24. The name resolves and serves. The first page loads only from its own origin (one script, one stylesheet, one icon). Its CSP is as in line 5, with `default-src 'none'` and `frame-ancestors 'none'`.
7. **Its core is open and free.** Signed out, `#/open/0695db52-5433-7332-8000-db7fe10da375` opened Moppetopia (153 elements, 378 links) and replaced the address with the world's own (`#/w/<id>`); an element link (`#/open/<world>/element/<id>`) opened that element. Its requests went only to its own host and www.onlyworlds.com, all GET. An id that is no public world asked for sign-in ("Sign in to open this world."). A world file or folder needs no account. The worlds you own or joined need a free onlyworlds.com account; a signed-in read was not run here. Nothing in the code is behind a payment.
