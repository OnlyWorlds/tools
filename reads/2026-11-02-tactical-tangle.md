1. **It is what it says.** The URL serves Tactical Tangle (200, "Tactical Tangle: Greek hoplite warfare"; the first screen offers Single player, Two players and Historical, and nothing else). The source is not public: the game's code is private, and the OnlyWorlds maintainers read it for this listing. Until `48436c3` (2026-11-02) the page was served with `X-Robots-Tag: noindex` as a pre-release game; that line is gone, and the game is public.
2. **Keys stay with the person.** Playing asks for no key. A world is connected by a pasted key, or by Sign in with OnlyWorlds, which makes a write key named `tangle` on a world the account owns (`src/ow/connection.ts:310-315`). That world key and its PIN, if one is given, are kept in the browser's localStorage, one slot per player (`tangle_ow_connect_p1`, `_p2`), until the person forgets or disconnects the world (`src/ow/connection.ts:103-111,321-337,376-385`, `src/utils/storage.ts:17-26`). A key Tangle made and no longer uses is revoked by its id at the next signed-in session; the list of those keeps ids and a key's last eight characters, never a key (`src/ow/take-back.ts:1-7,130-167`). The sign-in's account token is held in the page's memory only, never stored (`src/ow/signin.ts:4-7`, `src/screens/muster.ts:256-257`), and revoked by its id once a world is picked, when the account owns no world, when the player leaves the muster, and on `pagehide` (`src/screens/muster.ts:195-228,268-274,1218-1227`, `src/ow/signin.ts:233-249`). An account token pasted by hand is held in memory for the pick and not stored (`src/screens/muster.ts:1139-1156`). Across the sign-in round trip sessionStorage holds the parked muster (`tangle_signin_park`: the game state, with Character descriptions removed) and the SDK's own record (`ow_signin:tangle`: its `state`, PKCE verifier, return address and which player pressed); both are taken on any return, Back included (`src/ow/signin.ts:23-25,55-108,179-221`). The walk saw the same two writes at the press, and no token. Everything is sent only to www.onlyworlds.com, the SDK's default; the one override is for development builds only (`src/ow/dev-api-base.ts:17-28`). The host serves static files only (`wrangler.jsonc`: assets, no Worker script). The source is private: this line was read in it by the maintainer, and nobody outside can check it.
3. **It names itself.** Every SDK client it makes passes `client: 'tangle'` (`src/ow/sdk.ts:12,42,54`), which the SDK sends as `X-OW-Client` on element writes, here the record's bulk write; the one raw request, the token's revoke, sends `X-OW-Client: tangle` too (`src/ow/signin.ts:240`). Its sign-in is registered with OnlyWorlds as `tangle` ("Tactical Tangle") at https://tangle.onlyworlds.com/signin/callback (`GET /api/v2/auth/clients`, read 2026-11-02), the address it uses (`src/ow/signin.ts:18-19`); the walk's press went to https://www.onlyworlds.com/signin/authorize with `client_id=tangle`, that address, a `state` and an S256 code challenge (stopped there). Its own fields: `x_tangle_battle`, the tally on a battle's Event (`src/ow/record.ts:198-226`), and `x_tangle_trope`, the turning point on the trophy Object (`src/ow/record.ts:184`). It writes the record profile's mark `x_record` with `tool: 'tangle'` on the Event (`src/ow/record.ts:136-153,229`). It makes no folder or world file, so it writes no producer line.
4. **It speaks the wire.** It declares `@onlyworlds/sdk` 4.124.0 exactly (`package.json:37`, the same in `package-lock.json:525-527`). Its calls, each a route and method in the API document (https://www.onlyworlds.com/api/v2/openapi.json, read 2026-11-02): `GET /me`, `GET /world` and `GET /{type}` for character, collective, title, phenomenon and location (the SDK's list walk; `src/ow/connection.ts:227-240,261-264`); `GET /{type}/{id}` to settle a record whose answer was lost (`src/ow/record.ts:465`); `POST /bulk`, atomic, with `Idempotency-Key: tangle-<event id>` (`src/ow/record.ts:248,487`); and, signed in, `GET /account/worlds` (`src/ow/connection.ts:303`), `POST /account/worlds/{world_id}/keys` (`src/ow/connection.ts:311`), `DELETE /account/worlds/{world_id}/keys/{key_id}` (`src/ow/take-back.ts:155,177`), `POST /auth/token` (in the SDK) and `DELETE /account/tokens/{token_id}` (`src/ow/signin.ts:238-242`). The SDK sends a trailing slash (`/me/`, `/world/`, `/{type}/`, `/bulk/`) where the document has none, as Little Lens's read found; not re-run here. The battle record is the record profile's shape (schema-dist `profiles/record.md`): one atomic batch ordered Object, Event, Narrative so links point backward, each story Narrative on its own press, fresh ids only, never an edit of an existing element, supertype `Record` and subtype `Battle` on the Event (`src/ow/record.ts:160-288`); the mark's `played_at` is the press's clock in UTC with a `T` and `Z`, `version` a string (`1.7.0-s429`, `src/game/engine-version.ts:97`), `seed` a string, `outcome` one of `won`, `lost`, `drawn`, and `seats` only for the recorder's own Characters, who are also the Event's `characters` (`src/ow/record.ts:100-111,136-153,230`). The game's own tests at that commit read a built record back through the SDK's `recordsOf` and pass (the record, sign-in and connection suites: 3 files, 77 tests, run in a detached worktree). It writes no folder and no world file.
5. **What leaves the machine.** A world is read from, and a recorded battle written to, www.onlyworlds.com only, and only after the player connects a world and presses to record (`src/ow/record.ts:4-9`). The demo world, Moppetopia, is baked into the page and costs no request (`src/ow/demo-world.ts:1-22`; the walk saw none). The "share this battle" link carries the battle's whole setup in its address (`?b=`, compressed): any world Characters in the battle go with it, by id, name, title and the six numbers that differ from 50, never a key or a description (`src/game/share.ts:1-18,173-180,519`); it goes to whoever the player gives it, and, being the address's query, to tangle.onlyworlds.com when it is opened. There is no analytics, font or CDN call in the source or the served page: the icon font is bundled (`src/main.ts:5-6`), and the source links in the battle catalog are never rendered. Character pictures are never loaded. The page's CSP allows connections only to itself and www.onlyworlds.com, and images only from itself and `data:` (`public/_headers:24`). The source is private: this line was read in it by the maintainer, and nobody outside can check it.
6. **The host.** 200 over HTTPS with HSTS (`max-age=31536000`, since `df36af9`, as the other OnlyWorlds hosts send it); http redirects (301) to https. Re-read live after the go-public deploy: no `X-Robots-Tag`. Certificate verified, issued by Google Trust Services (WE1), subject `onlyworlds.com`, naming tangle.onlyworlds.com and `*.tangle.onlyworlds.com`, valid to 2026-12-13. The name resolves to Cloudflare and serves; it is a Worker serving static files (`wrangler.jsonc`). The first page loads only from its own origin (one script, one stylesheet); the icon font and eight sounds come from the same origin once a battle runs. Its CSP is as in line 5, with `default-src 'none'` and `frame-ancestors 'none'`; it also sends `X-Content-Type-Options: nosniff`.
7. **Its core is open and free.** Signed out, Single player opened a muster with an army already chosen; "take the field", then "advance", ran the battle (at 20x it ended in 8 seconds) to its aftermath (the chronicle and the tally), and "share this battle" gave a 1,223-character link. All 12 requests went to its own host, all GET; with no world connected the aftermath offers no record button. The demo world mustered with no account and no request, recording off. Two players and Historical were not walked. Connecting a world, by key or by sign-in, needs a free onlyworlds.com account, and recording a battle needs a key that can write. Nothing in the code is behind a payment or an invite.
