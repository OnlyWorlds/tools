1. **It is what it says.** The URL serves the mapper (200, "OnlyWorlds mapper": one script and one stylesheet from its own origin, `index.html` as built). The first page offers a world id field, Moppetopia and Sikelia as public worlds to try, and a read key field (`src/app.ts:97-123`). `?world=<id>` lists a world's Maps (`:349-406`), `&map=<id>` opens one (`:516-694`), and `&type=<type>&element=<id>` opens every Map a Pin places the element on, the first with the element selected and ringed (`:410-505`). It only reads: the one network module has a world read, `/me`, a get and a list, and nothing that writes (`src/net/api.ts:181-220`). The source is public under MIT (`LICENSE`).
2. **Keys stay with the person.** A public world needs no key. A private world is opened with a world key pasted into a password field (`src/app.ts:147-162`); it is read when the button is pressed and the field is cleared at once (`:170-171`); a 10-digit key and an account token are refused before anything is sent (`:173-176`). The key is held in the page object only (`:48`, set in `useKey` at `:208-214`), used only for the world it opens (`:238`), and handed to the SDK's client as its `apiKey` (`src/net/api.ts:155-156`), which sends it as `API-Key` (SDK `src/v2/client.ts:1879`) to `https://www.onlyworlds.com/api/v2` only (`src/net/api.ts:10`; the app sets no other base). No PIN is asked for or sent. The key is never written to the address (`src/core/address.ts:338-348`) or to history state (`:351-357`), and the read-only window the walks use exposes no key (`src/main.ts:239-283`). The code uses no localStorage, sessionStorage, IndexedDB or cookie: none in `src/`, and in the served script `sessionStorage` appears only in the SDK's sign-in helper, which the mapper never calls. The walk found nothing in localStorage, sessionStorage, IndexedDB or cookies after the visit. A reload asks for the key again. The host serves static files only (`wrangler.jsonc`: assets, no Worker script).
3. **It names itself.** Every SDK client it makes passes `client: 'mapper'` (`src/net/api.ts:156-157`), and the OnlyWorlds mark on a world's and an element's name is mounted with `tool: 'mapper'` (`src/app.ts:335,480`). The mapper writes nothing, and the SDK sends `X-OW-Client` only on element writes (SDK `src/v2/client.ts:1897-1899`), so the name is never sent: none of the walk's nine API requests carried it. It has no fields of its own and makes no folder or world file, so it writes no prefix and no producer line.
4. **It speaks the wire.** Every call is a GET, each a route in the API document (https://www.onlyworlds.com/api/v2/openapi.json, OpenAPI 3.1.0, read 2026-11-13 15:25Z), and each route the mapper uses takes a keyless reader (security `{}`) and a key: `GET /world` (`src/app.ts:181,246`); `GET /me`, with a pasted key only, no PIN (`:262`); `GET /{type}/{id}` for the element in the address, its type checked against the 22 first (`:416,425,442`); `GET /pin` with `element=<id>` and `expand=map` (`:433`); `GET /map` (`:297`); `GET /pin` for the whole world, only when the world counts at most 1,000 Pins (`:310-322`); `GET /pin` and `GET /marker` with `map=<id>` (`:638,649`); and `GET /zone` and `GET /{type}` with `ids` for the Zones the Markers name and the pinned elements' bodies (`:659,671`). Lists send `limit=1000` and follow `cursor` (`src/net/api.ts:194-207`); `ids` go at most 200 a call (`:210-220`, `src/core/slice.ts:92-96`). The document lists each of these parameters on these routes: `limit` (clamped 1 to 1000), `cursor`, `expand` (`map` is in the Pin's list), `ids` (at most 200), `map` on Pin and Marker, `element` on Pin, and `world` on every element list and get and on `GET /world`; all 22 types' list and get routes carry `limit`, `cursor`, `ids`, `expand` and `world`. A keyless read sends `world=<id>` and no credential (SDK `src/v2/client.ts:1867-1871`); a keyed read sends `API-Key` and no `world`. A 429 is waited out by its `RateLimit-Reset` or `Retry-After`, at most three times (`src/net/api.ts:144-153`). The SDK sends a trailing slash (`/world/`, `/pin/`) where the document has none, as Little Lens's read found; the live server answered all nine of the walk's API requests 200. It writes no folder and no world file.
5. **What leaves the machine.** A world is read from www.onlyworlds.com only, keyless or with the pasted key, and nothing is written anywhere. A Map's picture is loaded from the https address the world's Map gives it (`src/core/kinds.ts:47-49`, `src/core/rows.ts:123-131`), with a plain `fetch` that carries no key, or as a plain image when that host sends no CORS header (`src/view/picture.ts:137,146`); a Map whose picture is not on https is not drawn. So the host a world's author chose for a picture sees the reader's request, with the page's origin as its referrer (`Referrer-Policy: strict-origin-when-cross-origin`; the walk's requests carried `https://maps.onlyworlds.com/` and no query); for Moppetopia that host is media.onlyworlds.com. There is no analytics, error reporting, font or CDN call: the served script names no host but www.onlyworlds.com, the SVG namespace, a loopback address inside the SDK's sign-in error message, and the listed tools' own addresses, which are the OnlyWorlds mark's "Open with" rows (SDK `src/waymark/index.ts`, links only, no request; a row opens in a new tab only when the person presses it, carrying the world's id and the element's id); the stylesheet loads nothing; `font-src 'self'`. One thing leaves that is the host's, not the page's: the host sends Cloudflare's network error logging headers (`Report-To` and `NEL`, `success_fraction` 0, read live 2026-11-13), so a browser may report a request that failed, its address included, to a.nel.cloudflare.com; a request that succeeds is never reported. Cloudflare already serves the page and receives every request to it, so no one new sees an address. Tangle's and Windrose's reads say the same.

Certificate verified (TLS 1.3), issued by Google Trust Services (WE1), subject `onlyworlds.com`, naming onlyworlds.com, maps.onlyworlds.com and `*.maps.onlyworlds.com`, valid 2026-11-13 to 2027-02-11. Its CSP, on every file: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob: https:; font-src 'self'; connect-src 'self' https:; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'` (`public/_headers:8`). It also sends `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Cross-Origin-Opener-Policy: same-origin`, a `Permissions-Policy` that turns off the microphone, camera, location, payment, USB, serial and Bluetooth, `X-Robots-Tag: noindex` (and a robots meta, `index.html:6`), and Cloudflare's default `Report-To`/`NEL`.
