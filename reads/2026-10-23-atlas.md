# Atlas, read 2026-10-23

Read against the seven lines by the OnlyWorlds maintainer (Kael), at [atlas `d787ee2`](https://github.com/OnlyWorlds/atlas/tree/d787ee2) (1.85.0), the evidence below spot-checked again at `ebfb25c`, and at https://atlas.onlyworlds.com, signed out. Atlas is the crew's own tool, so it was read directly rather than through the form. File references are at that commit.

1. **It is what it says.** The URL serves Atlas; the source is public under MIT, with a NOTICE for the name and look.
2. **Keys stay with the person.** The world key, the PIN and the account token are stored in the browser's localStorage, in Atlas's worlds registry (`src/registry/registry.ts:105,142`). A linked folder's `world.json` `api` block carries the world key and world id, never the PIN, and an agent seat's secret is stripped at every write (`src/store/folder-store-fs.ts`, `withoutSeatSecret`). Atlas's host serves static files only.
3. **It names itself.** Every write sends `X-OW-Client: atlas` (`src/sync/ow-v2-client-adapter.ts:63,318`), and every SDK client it makes passes the same name. Its own fields use `atlas_`, the one older prefix the server keeps as written. A folder it makes gets the producer line `{tool: "atlas", version, input}` (`src/core/provenance.ts:36`).
4. **It speaks the wire.** Its sync calls `fetch` directly (as its README says) and the SDK elsewhere; every route either calls is in the API document (`/me`, `/world`, `/{type}`, `/{type}/{id}`, `/bulk`, `/changes`, `/world/proposals`, the media tickets, the account routes, `/join`). A folder Atlas wrote (live 1.85.0, a new world with a Character and a Location made in the UI, then Download the whole world) passes the folder lint of schema-dist serial 54 with 0 problems; that world held no links, filled fields or `atlas_` keys, so the lint saw those cases only through Atlas's other writers. Its world file is the SDK's `writeWorldFile`, and the downloaded file opens in the SDK's `readWorldFile`.
5. **What leaves the machine.** A world stays on your disk or in your browser; only a world you link sends its elements to www.onlyworlds.com and its images to upload.onlyworlds.com. An element's picture is fetched from its `image_url` with a plain GET, no key; Atlas allows a picture over plain http as well as https (the person's own image host is theirs to choose).
6. **The host.** 200 over HTTPS with HSTS (max-age 31536000); http redirects to https; certificate CN=atlas.onlyworlds.com, valid to 2027-01-07. The page loads only from its own origin. Its CSP allows connections only to itself, www.onlyworlds.com and upload.onlyworlds.com.
7. **Its core is open and free.** Making, browsing and editing worlds as folders needs no account. Linking to sync needs a free onlyworlds.com account (its sign-up asks for an email, a username and a password, no invite and no payment). Nothing in the code is behind a payment.
